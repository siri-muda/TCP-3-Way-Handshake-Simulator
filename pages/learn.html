The Mechanics of TCP Connection Establishment

The Transmission Control Protocol (TCP) operates at Layer 4 (Transport Layer) of the OSI model. Before any application bytes (such as web pages, emails, or files) can be exchanged, TCP must establish a reliable, bidirectional session using the 3-Way Handshake (SYN, SYN-ACK, ACK) defined in RFC 793.

1. What is TCP and What Does a "Handshake" Mean?

The Internet Protocol (IP) at Layer 3 is inherently unreliable and connectionless. IP packets can be dropped, duplicated, delayed, or delivered out of order. TCP sits directly on top of IP to transform this best-effort datagram channel into a reliable, ordered, and error-checked byte stream.

A handshake is an initial agreement protocol between two endpoints (Client and Server) before transmitting user payload. During this phase:

  • Both parties agree on Initial Sequence Numbers (ISNs) to track incoming and outgoing bytes.
  • Both hosts allocate operating system memory called Transmission Control Blocks (TCBs) and socket buffers.
  • Connection options are negotiated (such as Maximum Segment Size - MSS, and Window Scaling).
  • Both parties verify that bidirectional network connectivity actually works.
Key Concept: Without the handshake, neither endpoint would know what byte offsets to expect, making packet loss detection and byte reassembly impossible.

2. The Roles of TCP Control Flags (SYN, ACK, RST, FIN)

The standard TCP header is 20 bytes long (Data Offset = 5). Within the header lies a 6-bit field of control flags:

SYN (Synchronize)

Requests sequence number synchronization. Present only in the first packet sent by client (Step 1) and server (Step 2).

ACK (Acknowledgment)

Validates the 32-bit Acknowledgment Number field. Once a connection is active, almost all subsequent segments have ACK=1.

RST (Reset)

Aborts an invalid or rejected connection immediately. Returned when connecting to a closed port or when an unrecoverable error occurs.

FIN (Finish)

Signals graceful connection teardown when an application has finished streaming data.

PSH (Push)

Informs the receiving OS kernel to deliver data to the application buffer immediately without buffering.

URG (Urgent)

Indicates the Urgent Pointer field is valid, pointing to high-priority out-of-band data (e.g. Ctrl+C in Telnet).

3. Sequence & Acknowledgment Mathematics Explained

A common viva question is: "Why does the server acknowledge a SYN of Seq=1000 with Ack=1001 when no payload bytes were sent?"

The Phantom Byte Rule: In TCP, the Acknowledgment Number represents the next sequence number byte the receiver expects to receive.
If a SYN consumed 0 sequence numbers, the server's reply would have Ack=1000. But if client later transmitted 0-byte keepalive or repeated packet with Seq=1000, there would be ambiguity! To ensure that state transitions are guaranteed and reliable, RFC 793 mandates that SYN and FIN flags consume exactly 1 logical sequence number byte.
Step 1: Client sends [SYN] → Seq = Client_ISN, Ack = 0
Step 2: Server sends [SYN, ACK] → Seq = Server_ISN, Ack = Client_ISN + 1
Step 3: Client sends [ACK] → Seq = Client_ISN + 1, Ack = Server_ISN + 1

4. Deep Dive into the 3 Handshake Steps

Step 1: SYN

Client → Server

Client selects a 32-bit random Initial Sequence Number (e.g. 1000). Client sets SYN flag = 1. Client changes state from CLOSED to SYN-SENT.

Step 2: SYN-ACK

Server → Client

Server receives SYN on listening port. Sets state to SYN-RECEIVED. Acknowledges client SYN by setting Ack = 1001. Generates own ISN (e.g. 5000) and sets SYN=1, ACK=1.

Step 3: ACK

Client → Server

Client receives SYN-ACK and sets state to ESTABLISHED. Client transmits final ACK with Seq = 1001 and Ack = 5001. Server receives ACK and transitions to ESTABLISHED.

5. Real-World Lifecycle: What Happens When You Open https://example.com?

When a user types a URL into Google Chrome or Firefox, the network stack executes the following sequential stages:

  1. DNS Resolution: Browser queries a DNS resolver via UDP port 53 to map example.com to an IP address (e.g. 93.184.216.34).
  2. TCP 3-Way Handshake: Browser initiates TCP handshake on port 443 (HTTPS) or port 80 (HTTP) to establish the transport virtual circuit. (1 RTT)
  3. TLS Cryptographic Handshake: If HTTPS, client and server negotiate cipher suites and exchange certificates to establish TLS encryption keys.
  4. HTTP Request / Response: Browser transmits GET / HTTP/1.1. Server returns 200 OK with the HTML document.
  5. Connection Teardown: When done, the connection is cleanly closed using a 4-Way FIN/ACK handshake.

6. TCP vs UDP: Key Transport Layer Differences

Feature TCP (Transmission Control Protocol) UDP (User Datagram Protocol)
Connection Type Connection-oriented (Requires 3-way handshake) Connectionless (No handshake, sends immediately)
Reliability Guaranteed delivery with sequence ACK & retransmission Best-effort delivery (Packets may drop silently)
Data Ordering Strictly ordered (Reassembles out-of-order packets) No ordering guarantees (Packets processed as received)
Header Overhead 20 to 60 bytes 8 bytes fixed
Flow & Congestion Control Yes (Sliding window, slow-start, AIMD congestion) None (Transmits at whatever rate the app sends)
Primary Use Cases Web browsing (HTTP/HTTPS), Email (SMTP), File transfer (FTP/SSH) Live video streaming, VoIP, Gaming, DNS queries

7. High-Yield Viva Examination Q&A

Q1. Why are Initial Sequence Numbers (ISNs) randomized instead of always starting at 0?
Answer: Security and collision avoidance. If sequence numbers always started at 0, an attacker could easily guess sequence numbers to perform TCP sequence prediction attacks and session hijacking. Furthermore, randomizing ISNs prevents packets from older dead connections from being misinterpreted as belonging to a newly opened connection.
Q2. What is a SYN Flood attack and how do SYN Cookies mitigate it?
Answer: An attacker sends massive volumes of spoofed SYN packets without ever completing the handshake with the final ACK. The server allocates TCB memory for each half-open connection until its backlog is exhausted, crashing legitimate access. SYN Cookies solve this by encoding state mathematically inside the server's ISN without allocating memory until the final valid ACK arrives.
Q3. Can application payload data be sent in the 3rd step of the handshake?
Answer: Yes! Per RFC 793, the client has already validated the server's SYN-ACK and is officially in ESTABLISHED state. Therefore, the client is allowed to piggyback HTTP GET data inside the 3rd packet (ACK).
Q4. What is the difference between TCP Flow Control and Congestion Control?
Answer: Flow control protects the receiver from being overwhelmed by a faster sender using the 16-bit Window Size field. Congestion control protects the intermediate network and routers from bottleneck congestion using Congestion Window (cwnd) algorithms like Slow Start and Congestion Avoidance.
